Технический проект
==================


1. Назначение документа
-----------------------


Документ описывает архитектуру и принятые решения для учебной программы, которая преобразует HTML-строку в упрощённое дерево документа. Технический проект соответствует фактически имеющимся модулям ``lexer.py``, ``html_parser.py`` и ``main.py``.

2. Общая схема
--------------


.. code-block:: text

   main.py
     └─ parse_html(html_text)
          ├─ init_lexer(html_text)
          ├─ get_next_token()  ← lexer.py
          └─ Node (дерево документа)
     └─ format_tree(root)
          └─ вывод строкового представления в консоль


Программа работает локально и синхронно. Внешние сервисы и сторонние библиотеки не используются.

3. Структура модулей
--------------------


3.1. ``lexer.py``
^^^^^^^^^^^^^^^^^


Хранит исходную строку, позицию чтения и состояние разбора: нахождение внутри тега или значения атрибута в кавычках. ``init_lexer(html_text)`` сбрасывает состояние и устанавливает первый символ. ``get_next_token()`` продвигает разбор и возвращает пару ``(тип, значение)`` либо ``None``.

Пробельные символы вне значений атрибутов пропускаются. Текстовый фрагмент очищается методом ``strip()``. Значение атрибута в кавычках возвращается отдельным токеном ``STRING_VAL``; кавычки выдаются отдельными токенами ``QUOTE``.

3.2. ``html_parser.py``
^^^^^^^^^^^^^^^^^^^^^^^


Определяет структуру ``Node``, функцию ``parse_html(html_text)`` и функцию ``format_tree(node, indent=0)``. Построитель последовательно получает токены лексера, создаёт узлы и связывает их через списки ``children``.

3.3. ``main.py``
^^^^^^^^^^^^^^^^


Содержит пример HTML-фрагмента, вызывает ``parse_html``, затем печатает результат ``format_tree``. Ввод из файла или пользовательский ввод не реализованы.

4. Модель данных
----------------


Узел ``Node`` имеет следующие поля:

.. list-table::
   :header-rows: 1

   * - Поле
     - Тип
     - Назначение
   * - ``kind``
     - ``str``
     - Вид узла: ``document``, ``element``, ``text`` или ``comment``
   * - ``name``
     - ``Optional[str]``
     - Имя документа или HTML-элемента
   * - ``text``
     - ``Optional[str]``
     - Текстовое содержимое текстового узла или комментария
   * - ``attributes``
     - ``Dict[str, Optional[str]]``
     - Атрибуты элемента; ``None`` означает атрибут без значения
   * - ``children``
     - ``List[Node]``
     - Дочерние узлы в порядке следования во входе


Корневой узел имеет ``kind="document"`` и ``name="#document"``. Узлы текста и комментариев добавляются в ``children`` текущего родителя.

5. Алгоритм построения дерева
-----------------------------


1. ``parse_html`` вызывает ``init_lexer``, создаёт корневой узел документа и стек, содержащий этот корень.
2. Парсер получает токены вызовами ``get_next_token`` до получения ``None``.
3. При токене ``TEXT`` создаётся текстовый узел и добавляется к верхнему элементу стека.
4. При токене ``COMMENT`` создаётся узел комментария и добавляется к текущему родителю.
5. После ``TAG_OPEN`` вспомогательный разбор считывает токены до ``TAG_CLOSE``, выделяет признак закрывающего тега, имя и атрибуты.
6. Для открывающего тега создаётся элемент и добавляется к текущему родителю. Значения атрибутов собираются из последовательностей ``NAME``, ``EQUALS``, ``QUOTE`` и ``STRING_VAL``.
7. Обычный открывающий элемент помещается на стек. Самозакрывающиеся и перечисленные в ``_VOID_ELEMENTS`` элементы на стек не помещаются.
8. Для закрывающего тега парсер ищет совпадающее имя в стеке сверху вниз. При совпадении удаляет найденный элемент и всё, что находилось над ним. Если совпадения нет, тег игнорируется.
9. ``format_tree`` рекурсивно формирует строки с отступом в два пробела на уровень вложенности.

6. Интерфейсы модулей
---------------------


- ``init_lexer(html_text: str) -> None`` — подготовить лексер к новой строке.
- ``get_next_token()`` — вернуть следующий токен ``(тип, значение)`` или ``None``.
- ``parse_html(html_text: str) -> Node`` — построить дерево документа.
- ``format_tree(node: Node, indent: int = 0) -> str`` — вернуть форматированное текстовое представление дерева.
- ``Node.add_child(node: Node) -> None`` — добавить дочерний узел.

7. Обработка некорректного или неполного HTML
---------------------------------------------


Реализован упрощённый механизм восстановления: неподходящий закрывающий тег пропускается; если закрывающий тег совпал с элементом ниже вершины стека, незакрытые потомки над ним снимаются со стека. При достижении конца входа оставшиеся открытые элементы остаются в дереве. Строгая диагностика синтаксических ошибок не предусмотрена.

Лексер хранит состояние в переменных модуля, поэтому разбор выполняется последовательно. Одновременные или вложенные вызовы ``parse_html`` в разных потоках не поддерживаются.

8. Развёртывание и запуск
-------------------------


Сторонние зависимости отсутствуют. Из корневой папки проекта запускается команда:

.. code-block:: text

   python main.py


В качестве результата в стандартный вывод направляется дерево тестового HTML-фрагмента.

9. Ограничения и дальнейшее развитие
------------------------------------


Текущий лексер не декодирует HTML-сущности, а парсер не реализует полный стандарт HTML, обработку ``doctype``, специальные правила ``script`` и ``style``, CSS, JavaScript и визуальный рендеринг. В следующих версиях можно добавить загрузку HTML из файла, диагностику ошибочной разметки, тесты для отдельных токенов и форм дерева, а затем отдельный компонент визуализации.
