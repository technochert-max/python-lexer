Техническое задание
===================


1. Назначение продукта
----------------------


Разрабатывается настольный веб-браузер для просмотра страниц с HTML-разметкой и CSS-оформлением. Документ описывает программу с точки зрения пользователя: какие элементы интерфейса он видит, какие действия может выполнить и какой результат получает.

Браузер не исполняет JavaScript. Страницы, содержание и оформление которых доступны без JavaScript, должны открываться и отображаться. Функции сайтов, которым необходим JavaScript, могут быть недоступны.

2. Для кого предназначена программа
-----------------------------------


Программа предназначена для пользователей, которым нужно:

- просматривать веб-страницы;
- открывать сохранённые на компьютере HTML-документы;
- переходить по ссылкам и возвращаться к ранее открытым страницам;
- просматривать страницы с их CSS-оформлением;
- читать материалы и пользоваться стандартными элементами HTML-форм, не зависящими от JavaScript.

3. Главное окно браузера
------------------------


При запуске пользователь видит окно браузера со следующими элементами:

1. **Панель вкладок** — показывает открытые страницы и позволяет переключаться между ними, открывать новую и закрывать ненужную вкладку.
2. **Адресная строка** — показывает адрес текущей страницы и позволяет ввести новый адрес или выбрать локальный HTML-файл.
3. **Кнопка «Назад»** — возвращает к предыдущей странице в текущей вкладке.
4. **Кнопка «Вперёд»** — снова открывает страницу, к которой пользователь вернулся кнопкой «Назад».
5. **Кнопка «Обновить»** — повторно загружает текущую страницу.
6. **Кнопка «Закладки»** — позволяет сохранить текущую страницу в закладки и открыть сохранённую страницу.
7. **Область страницы** — показывает содержимое текущей веб-страницы или локального документа.

Заголовок вкладки и окна должен отражать название страницы, если оно задано. Пока страница загружается, пользователь должен видеть, что загрузка ещё не завершена.

4. Действия пользователя и ожидаемый результат
----------------------------------------------


4.1. Открытие страницы
^^^^^^^^^^^^^^^^^^^^^^


Пользователь может ввести веб-адрес в адресную строку и подтвердить переход. Браузер открывает страницу в текущей вкладке. Пользователь также может выбрать HTML-файл на компьютере и просмотреть его в браузере.

Если адрес или файл открыть не удалось, браузер показывает сообщение с понятным описанием проблемы и предлагает вернуться назад или повторить загрузку.

4.2. Просмотр страницы
^^^^^^^^^^^^^^^^^^^^^^


В области страницы пользователь видит текст, заголовки, списки, таблицы, изображения, ссылки и другие поддерживаемые элементы. CSS-оформление страницы должно быть заметно при просмотре: цвета, шрифты, размеры, отступы, границы и расположение элементов.

Если содержимое страницы длиннее видимой области, пользователь может прокручивать его. При изменении размера окна страница должна подстраиваться под новую ширину и высоту. Пользователь может увеличить или уменьшить масштаб, а также вернуть исходный масштаб.

4.3. Переходы по ссылкам
^^^^^^^^^^^^^^^^^^^^^^^^


Нажатие на ссылку открывает указанную страницу или перемещает пользователя к соответствующему месту текущей страницы. Пользователь может открыть ссылку в текущей вкладке либо выбрать открытие в новой вкладке.

Кнопки «Назад» и «Вперёд» управляют историей переходов отдельно для каждой вкладки. Если перехода в выбранном направлении нет, соответствующая команда недоступна.

4.4. Работа с вкладками
^^^^^^^^^^^^^^^^^^^^^^^


Пользователь может открыть несколько страниц одновременно, переключаться между ними и закрывать вкладки. При закрытии вкладки остальные вкладки продолжают работу.

4.5. Закладки
^^^^^^^^^^^^^


Пользователь может добавить текущую страницу в закладки, увидеть подтверждение сохранения и открыть её позже из списка закладок. Закладки должны сохраняться между запусками программы.

4.6. Формы и элементы управления
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^


Пользователь может просматривать и, где это предусмотрено страницей, заполнять стандартные поля HTML: текстовые поля, флажки, переключатели, списки и многострочные поля. Если форма отправляется обычным способом и не требует JavaScript, браузер выполняет отправку и показывает полученный результат.

Если элемент не работает из-за отсутствия JavaScript, браузер не должен изображать, будто действие выполнено. Пользователь должен получать понятный результат: например, элемент остаётся без реакции или показывается сообщение о том, что функция страницы требует JavaScript.

5. Отображение HTML и CSS
-------------------------


Браузер должен показывать типичные страницы, построенные из HTML и CSS, в виде, удобном для чтения и просмотра. К видимому содержимому относятся:

- текст, заголовки, абзацы, списки и таблицы;
- ссылки и стандартные элементы форм;
- изображения и другие поддерживаемые встроенные материалы;
- оформление страницы: цвет и фон, шрифты, размеры, отступы, границы и расположение элементов;
- варианты расположения, рассчитанные на разные размеры окна.

Если отдельный элемент страницы не поддерживается или не может быть загружен, пользователь всё равно должен иметь возможность просматривать остальную часть страницы. Браузер должен по возможности ясно обозначать, что именно не загрузилось или не поддерживается.

Внешний вид отдельных сайтов может отличаться от других браузеров. Основные элементы и возможности, которые поддерживаются в каждой версии программы, должны быть перечислены в пользовательской справке или списке совместимости.

6. JavaScript и ограничения для пользователя
--------------------------------------------


Браузер не запускает JavaScript-код страниц. Это относится к сценариям, обработчикам событий и адресам, которые пытаются выполнить JavaScript.

Пользователь может столкнуться с тем, что сайт открывается, но часть его возможностей не работает: например, динамическое меню, автоматическое обновление содержимого, авторизация или интерактивное приложение. Это ограничение должно быть объяснено в справке и, когда возможно, рядом с недоступной функцией.

JavaScript-зависимая функция не должна мешать чтению той части страницы, которая доступна как HTML и CSS.

7. Сообщения и понятность интерфейса
------------------------------------


Браузер должен показывать пользователю понятные сообщения, если:

- страница или файл не найдены;
- отсутствует подключение к сети или сервер не отвечает;
- страницу нельзя открыть из-за ошибки защищённого соединения;
- изображение или другой материал страницы не загрузился;
- часть возможностей страницы требует JavaScript.

Сообщение должно кратко объяснять проблему и, где уместно, давать действие для продолжения: повторить загрузку, вернуться назад или закрыть сообщение.

8. Удобство использования
-------------------------


- Основные команды должны быть доступны мышью и клавиатурой.
- Пользователь должен видеть, какая вкладка выбрана и какая страница открыта.
- Фокус клавиатуры должен быть заметен при переходе между ссылками и элементами управления.
- Увеличение масштаба не должно делать основные элементы управления браузера недоступными.
- При неожиданной ошибке одной страницы окно браузера и остальные вкладки должны оставаться доступными.

9. Границы продукта
-------------------


В первой версии браузер не предназначен для:

- запуска JavaScript и работы сайтов, полностью зависящих от него;
- установки браузерных расширений;
- синхронизации вкладок и закладок между устройствами;
- редактирования HTML-страниц;
- гарантированного воспроизведения любых аудио-, видео- и иных форматов.

10. Сценарии приёмки с точки зрения пользователя
------------------------------------------------


1. Пользователь запускает программу и видит окно браузера с адресной строкой, вкладками и областью страницы.
2. Пользователь открывает локальный HTML-файл и видит его текст, изображения и CSS-оформление, если эти материалы доступны.
3. Пользователь вводит веб-адрес и получает страницу в области просмотра либо понятное сообщение об ошибке.
4. Пользователь переходит по ссылке, возвращается кнопкой «Назад», затем снова переходит вперёд.
5. Пользователь открывает ссылку в новой вкладке, переключается между вкладками и закрывает одну из них, не закрывая остальные.
6. Пользователь добавляет страницу в закладки, закрывает программу, запускает её снова и открывает сохранённую закладку.
7. Пользователь изменяет масштаб и размер окна и может продолжать читать страницу.
8. Пользователь может взаимодействовать с поддерживаемыми HTML-формами, не требующими JavaScript.
9. На странице с JavaScript пользователь видит доступное HTML/CSS-содержимое, а JavaScript-зависимые функции не исполняются и не выдаются за работающие.
10. Ошибка загрузки страницы или отдельного ресурса отображается понятным сообщением, при этом браузер остаётся работоспособным.

11. Текущее состояние проекта
-----------------------------


Имеющийся проект пока является консольным прототипом: он разбирает простой HTML-фрагмент и выводит упрощённое дерево. Пользовательское окно браузера, загрузка страниц, вкладки, закладки и отображение CSS относятся к последующей разработке и не считаются уже реализованными возможностями.
