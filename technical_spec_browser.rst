Техническое задание
====================

Разработка учебного веб-браузера на Python
------------------------------------------

1. Общие сведения
-----------------

Наименование проекта: учебный веб-браузер на языке Python.

Тип проекта: учебный программный проект.

Язык программирования: Python.

Основное назначение проекта: разработка браузера, который позволяет пользователю
открывать веб-страницы, переходить между ними и взаимодействовать с содержимым
сайтов. Проект разрабатывается поэтапно. Первым этапом является создание
лексического анализатора, предназначенного для обработки текста и/или отдельных
элементов веб-страницы в рамках дальнейшего развития браузера.

2. Цели и задачи разработки
---------------------------

Цель проекта — получить работающий учебный браузер и изучить основные принципы
обработки веб-страниц, сетевого взаимодействия и организации программных
модулей.

Для достижения цели необходимо решить следующие задачи:

* разработать модульную структуру приложения;
* реализовать первоначальный лексический анализатор;
* определить формат данных, передаваемых между компонентами браузера;
* обеспечить возможность дальнейшего добавления загрузки, разбора и отображения
  веб-страниц;
* предусмотреть обработку ошибок и некорректных входных данных;
* подготовить тесты и краткую документацию.

3. Область применения
---------------------

Программа предназначена для учебного использования, демонстрации принципов
устройства браузеров и последовательной реализации компонентов, необходимых
для обработки веб-содержимого.

На текущем этапе проект не обязан обеспечивать полную совместимость с
современными браузерами и всеми веб-стандартами.

4. Функциональные требования
----------------------------

4.1. Общие требования к приложению
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Приложение должно иметь структуру, позволяющую разрабатывать и проверять
компоненты независимо друг от друга. Основные функции браузера должны
добавляться постепенно, без необходимости полной переработки уже реализованных
модулей.

4.2. Лексический анализатор
~~~~~~~~~~~~~~~~~~~~~~~~~~~

Лексический анализатор является первым реализуемым компонентом проекта.
Он должен принимать входную последовательность символов и выделять в ней
лексические единицы согласно определённым правилам.

Анализатор должен:

* последовательно обрабатывать входной текст;
* распознавать поддерживаемые типы лексем, определённые реализацией;
* сохранять значение каждой распознанной лексемы и её тип;
* возвращать результат в форме, пригодной для дальнейшей обработки другими
  компонентами;
* корректно обрабатывать пустой ввод и пробельные символы;
* сообщать об ошибках или обозначать неподдерживаемые последовательности,
  если они встречаются во входных данных.

Точный перечень лексем и правила их распознавания должны соответствовать
реализации анализатора и уточняться по мере развития проекта.

4.3. Дальнейшее развитие браузера
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Архитектура проекта должна допускать последующее добавление следующих функций:

* ввод URL-адреса;
* загрузка содержимого веб-страницы;
* разбор HTML и других необходимых форматов;
* обработка CSS для определения оформления;
* построение внутреннего представления страницы;
* отображение текста, ссылок и базовых элементов страницы;
* переход по ссылкам и возврат к предыдущей странице;
* обработка сетевых ошибок и ошибок разбора содержимого.

Перечисленные возможности являются целями дальнейшего развития и не считаются
обязательными для первой версии, если они не реализованы в рамках текущего этапа.

5. Нефункциональные требования
------------------------------

Программа должна удовлетворять следующим требованиям:

* **Модульность:** компоненты приложения должны быть разделены по назначению.
* **Читаемость:** исходный код должен иметь понятные имена классов, функций и
  переменных.
* **Расширяемость:** новые функции должны добавляться без существенного изменения
  базовой структуры проекта.
* **Надёжность:** некорректные входные данные не должны приводить к
  необработанному аварийному завершению программы в типичных сценариях.
* **Переносимость:** проект должен запускаться в среде с совместимой версией
  Python и необходимыми зависимостями.
* **Тестируемость:** ключевые алгоритмы должны допускать проверку на отдельных
  наборах входных данных.

6. Требования к реализации
--------------------------

Проект должен быть реализован на Python. Структура файлов и модулей должна
соответствовать фактической организации проекта.

Лексический анализатор следует отделить от точки входа приложения. Интерфейсы
между компонентами должны быть достаточно простыми и документированными, чтобы
результаты анализа можно было использовать в следующих этапах разработки
браузера.

Внешние библиотеки допускается использовать при необходимости. Используемые
зависимости должны быть перечислены в документации проекта.

7. Требования к интерфейсу
--------------------------

В первой версии допускается консольный интерфейс для проверки работы
лексического анализатора. По мере развития проекта может быть реализован
графический интерфейс или оконное отображение веб-страниц.

Если интерфейс предусмотрен текущей версией, пользователь должен иметь
возможность передать входные данные и просмотреть результат обработки либо
понятное сообщение об ошибке.

8. Требования к тестированию
----------------------------

Для проверки программы необходимо подготовить тесты, включающие:

* обычный корректный входной текст;
* пустую строку;
* текст с пробелами и переносами строк;
* входные данные с несколькими типами поддерживаемых лексем;
* неизвестные или некорректные последовательности;
* повторный запуск анализа с разными входными данными.

Для каждой проверки следует определить ожидаемый результат и сравнить его с
фактическим результатом работы программы.

По мере добавления новых компонентов браузера необходимо дополнять набор
тестов проверками загрузки, разбора и отображения веб-страниц.

9. Этапы разработки
-------------------

1. Анализ требований и определение целей первой версии.
2. Проектирование структуры модулей.
3. Разработка и проверка лексического анализатора.
4. Определение интерфейсов взаимодействия между компонентами.
5. Реализация загрузки и разбора веб-содержимого на последующих этапах.
6. Реализация отображения страниц и базовой навигации.
7. Тестирование, исправление ошибок и подготовка документации.

Этапы 5 и 6 выполняются в рамках дальнейшего развития проекта и могут быть
разделены на отдельные учебные итерации.

10. Критерии приёмки
--------------------

Первая версия проекта считается выполненной, если:

* приложение запускается в предусмотренной среде;
* лексический анализатор принимает входные данные и возвращает результат;
* поддерживаемые лексемы распознаются согласно заданным правилам;
* пустой и некорректный ввод обрабатываются предсказуемо;
* результат анализа можно использовать в последующих модулях;
* структура кода допускает дальнейшее развитие проекта;
* подготовлены инструкции по запуску и тестовые примеры.

Готовность полноценного браузера оценивается отдельно после реализации
загрузки, разбора и отображения веб-страниц.

11. Документация
----------------

В комплект проекта должны входить:

* исходный код;
* инструкция по установке зависимостей и запуску;
* описание структуры модулей;
* описание поддерживаемых возможностей анализатора;
* тестовые примеры и результаты проверки;
* краткое описание текущих ограничений и планируемых улучшений.

12. Ограничения первой версии
-----------------------------

Первая версия является учебным прототипом. Она не обязана поддерживать все
веб-стандарты, выполнять JavaScript, обеспечивать полноценную безопасность
песочницы, поддерживать все типы мультимедиа или корректно отображать каждую
современную веб-страницу.

Перечисленные возможности могут рассматриваться как отдельные задачи будущих
этапов разработки.
